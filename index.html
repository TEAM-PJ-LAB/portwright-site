The problem

The fix exists. It doesn't fit your tree.

Vendor kernels drift

A vendor BSP kernel branches from an LTS release and adds its own drivers and board code. The further it drifts, the more upstream and stable patches fail to apply as written.

Every bugfix can be a CVE

The kernel CVE team assigns CVEs to any bugfix it identifies once the fix reaches a stable tree, and recommends taking all stable updates.[1] A frozen vendor kernel can't take them wholesale, so teams port fixes one at a time.

Regulators now ask

Under the EU Cyber Resilience Act, manufacturers must report actively exploited vulnerabilities from 11 September 2026, starting with a 24-hour early warning. Most other obligations apply from 11 December 2027.[2][3]

Why a clean apply isn't enough

Applying is not the same as fixing.

Patch tools place a hunk by matching the lines around it. When two functions share those lines, a hunk can land in the wrong one and still apply without a warning. Portwright treats a clean apply as the first of four checks.

Verification

Four gates before your engineers look at it.

  1. G1 apply

    Applies

    The patch passes git apply --check on a clean checkout of your vendor tree.

    $ git apply --check fix.patchok
  2. G2 build

    Compiles

    Every touched C file is cross-compiled for your target. A warning the unpatched tree doesn't have counts as a failure.

    $ make ARCH=arm64 drivers/net/ring.ono new warnings
  3. G3 match

    Matches

    When a human stable backport exists, the changed lines are compared with it. Every difference gets a written review.

    # compare with stable backportequivalent
  4. G4 boot

    Boots

    All patches are applied together, and the kernel is built and booted in QEMU.

    $ qemu-system-aarch64 -M virt ...init reached

Log lines are illustrative.

What the gates don't prove yet

  • A patch that compiles and boots can still miss the bug at runtime. Reproduction tests and KUnit checks are next.
  • The boot check only runs code built into the kernel image. Fixes inside modules are covered by the compile gate.
  • Equivalence review is done by AI today. Blind review by kernel engineers comes next.
